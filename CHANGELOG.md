# Changelog

Format: [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), versions [SemVer](https://semver.org/).

## [Unreleased]

### Added
- `Quill.Code.CSharp.Linq` separated from the engine: it now only depends on EF Core Relational; the engine is an `ILinqDatabaseProvider` (column types, provider assemblies, connection string, `Configure` of the context) passed to `LinqLanguageOptions.Provider` and to `LinqQueryExecutor(provider)` (instead of `applicationName`). `Quill.Code.CSharp.Linq.SqlServer`: `SqlServerLinqProvider(applicationName)`.
- `Quill.Code.CSharp.Linq` (net10.0, EF Core), taken from `Querify.Languages.Linq`: LINQ / EF queries on a DbContext generated from a `SqlDatabaseSchema`. `LinqLanguageService(LinqLanguageOptions)` for the editor (structure read again on each request, parameters as variables); `LinqQueryExecutor` on the contract of `SqlServerQueryExecutor`: `RunAsync` with no return value (Dump through `Data`, generated SQL, `Log.*` and errors through `Log`, cancellation thrown), `ReadAsync` returns the last Dump and throws its errors. Generation, compilation and caches are internal.

### Changed
- NuGet packages published under the `QuillCode.*` IDs (`QuillCode.CSharp`, `QuillCode.Sql.SqlServer`, `QuillCode.Data.Sql`…): the `Quill.` prefix is reserved on nuget.org. Assemblies and namespaces unchanged.
- CI: versions published on nuget.org (trusted publishing) on each `v*` tag; no more packages on GitHub Packages nor automatic pre-releases from `master`.
- SQL execution grouped under `Quill.Code.Sql`: `Quill.Code.SqlServer`, `Quill.Code.MySql`, `Quill.Code.PostgreSql`, `Quill.Code.Oracle` and `Quill.Code.Sqlite` become `Quill.Code.Sql.[Engine]` (folders, projects, packages, namespaces); the new `Quill.Code.Sql` project receives `ISqlQueryExecutor`, `DbQueryExecutor` and `DbResultSetReader` (namespace `Quill.Code.Sql.Execution`, previously `Quill.Code.Execution`).
- `QueryParameter` and `QueryParameterType` move from `Quill.Code.SqlServer.Execution` to `Quill.Code.Execution`, `QueryExecutionLimits` from `Quill.Code.SqlServer.Constants` to `Quill.Code.Constants`: shared by SQL and LINQ execution.
- `Quill.Code.Sql` renamed `Quill.Code.SqlServer` (folder, project, namespaces): T-SQL, ScriptDom and execution through Microsoft.Data.SqlClient tie it to SQL Server; the neutral model stays `Quill.Data.Sql`.
- Constants grouped in the `Constants/` folder of each project (namespace `<Project>.Constants`): `CodeLanguages` moves from `Quill.Code.Languages` to `Quill.Code.Constants`; `CompletionFilter.DefaultMaxResults` becomes `CompletionConstants.DefaultMaxResults`, `SyntaxDefinition.LineCommentProperty` `HighlightingConstants.LineCommentProperty`, `SqlDatabaseSchema.DefaultSchema` `SqlSchemaConstants.DefaultSchema`; `QueryExecutionLimits` moves to `Quill.Code.SqlServer.Constants`.
- `Quill.Code.CSharp` simplified: `CSharpLanguageService(Func<CSharpLanguageOptions>?)` is the only entry point (project name in the options); sources on the fly are exposed on it directly (`SetSource`, `SetSourceFileAsync`, `RemoveSource`, `ClearSources`, `Sources`, `SourcesChanged`). The service is no longer `IDisposable`: the Roslyn host is shared and projects are snapshots.
- `CSharpProjectOptions` becomes `CSharpLanguageOptions`; `CSharpReferences` moves to `Quill.Code.CSharp`. `SourceTransform` returns a string of the same length as the text (no more generated code wrapper).
- `ICodeLanguageProvider` becomes `ICodeLanguageService`.

### Removed
- `CSharpWorkspace`, `CSharpCompletionService`, `CSharpDiagnosticService`, `CSharpHoverService`, `CSharpSignatureService`, `CSharpSource`, `CSharpLanguageOptions.AllowImports`; `CSharpProject`, `CSharpDocument` and `CSharpDiagnosticMapper` become internal.
- `ICodeCompilation` (empty) and `CodeLanguageServiceProvider` (unused static registry).

### Added
- Timestamped `LogEntry(Level, Text, Source)` (`Timestamp`), execution message to keep or display; `LogSource` (`Host`, `Code`) carries its origin, `LogLevel` remaining a severity aligned with Microsoft.Extensions.Logging. `RunOptions.Log` receives a `LogEntry`.
- `Quill.Code.Execution`: shared execution options `RunOptions` (`Log`) and `DataRunOptions` (`Log` + `Data`, each result set handed over as soon as it is read); `CSharpCompileOptions` inherits from `RunOptions`; `ISqlQueryExecutor.ExecuteAsync` becomes `RunAsync`, with no return value: PRINT, affected rows and SQL errors through `Log`, result sets through `Data`, cancellation thrown; `QueryExecutionResult`, `QueryMessage` and `QueryMessageKind` go back to Querify. `QueryResultSet`, `QueryResultColumn` and `QueryResultRow` move from `Quill.Code.SqlServer.Execution` to `Quill.Code.Execution`.
- `CSharpLanguageService.RunAsync`: compiles, runs the entry point and unloads the assembly in one call, with no return value (output through `CSharpCompileOptions.Log`); a compilation failure throws `CSharpCompilationException` (diagnostics).
- `Quill.Code.SqlServer`: SQL execution on a connection string (`ISqlQueryExecutor`, `SqlServerQueryExecutor`: scripts split on GO like SSMS, parameterized queries); `Quill.Code.SqlServer.Execution`: the results (`QueryExecutionResult`, `QueryResultSet`, `QueryResultColumn`, `QueryResultRow`, `QueryMessage`, `QueryMessageKind`, `QueryParameter`, `QueryParameterType`, `QueryExecutionLimits`), taken from Querify. `Quill.Code.SqlServer` now depends on Microsoft.Data.SqlClient.
- `Quill.Data.Sql`: structure of a database (`SqlDatabaseInfo`, `SqlDatabaseSchema`, `SqlSchemaObject`, `SqlColumn`, `SqlSchemaObjectKind`), taken from Querify.Databases, and the `ISqlSchemaReader` contract; `Quill.Data.Sql.SqlServer`: `SqlServerSchemaReader`. `Quill.Code.SqlServer` uses this model (its own schema types are removed); `SqlColumn` is now built through properties (`new SqlColumn(name, type) { IsNullable = false, PrimaryKeyOrdinal = 1 }`).
- `Quill.Code.SqlServer`: completion and hover on a catalog provided by the host (`ISqlCatalog`, `SqlDatabaseInfo` / `SqlDatabaseSchema` / `SqlSchemaObject` / `SqlColumn` model, in-memory `SqlCatalog`), built-in T-SQL keywords, host variables (`SqlVariable`); `SqlLanguageService(SqlLanguageOptions)` replaces the constructor with replaceable services, per-feature services become internal.
- `CompletionFilter.Filter`: filters and sorts suggestions on the current word (starts with, segment start, contains), taken from Querify.
- Solution structure: `Quill.Code`, `Quill.Code.CSharp`, `Quill.Code.SqlServer`, `Quill.Code.Tests`.
- `Quill.Code.CSharp`: `CSharpLanguageService` delegates to `CSharpCompletionService`, `CSharpDiagnosticService`, `CSharpHoverService` and `CSharpSignatureService` (`ICodeCompletion`, `ICodeDiagnostic`, `ICodeHover`, `ICodeSignature`), usable alone on a `CSharpProject` (exposed by `CSharpLanguageService.Completion`, `.Diagnostics`, `.Hover`, `.Signature`, with overloads on a `CSharpDocument`).
- Removal of `ICSharpLanguageService` (apps use `CSharpLanguageService`, which implements `ICodeLanguageProvider`) and of `CSharpLanguageServiceExtensions` (replaced by the feature services).
- `Quill.Code.SqlServer`: `SqlLexer`, `SqlContextAnalyzer` (`Analyze`, `AnalyzeScope`: expected input kind, qualifier, tables and aliases of the current GO batch, database of the last `USE`), `SqlSyntaxChecker` (ScriptDom diagnostics, GO batches included) and `SqlLanguageService` (`ICodeLanguageProvider`) delegating to `SqlCompletionService`, `SqlDiagnosticService`, `SqlHoverService` and `SqlSignatureService` (real diagnostics; the others suggest nothing); the host can replace each service with its own.
- Centralized package versions, NuGet metadata, Source Link.
- CI: build and tests, publication on GitHub Packages on each `v*` tag.
- Shared models: completion (`CompletionItem`, `CompletionItemKind`, `CompletionList`, `CompletionChange`, `CompletionTrigger`), analysis (`CodeDiagnostic`, `CodeDiagnosticSeverity`, `HoverInfo`, `SignatureHelpInfo`, `SignatureInfo`) and `LinePosition`.
- `Quill.Code.CSharp`: `CSharpWorkspace`, `CSharpProject`, `CSharpDocument`, `CSharpReferences`; `ICSharpLanguageService` (completion with change computation, diagnostics, hover, signature help); `AddQuillCSharp()`.
- Syntax highlighting (`Quill.Code.Highlighting`): `XshdReader` (AvalonEdit .xshd format), `SyntaxDefinition`, `SyntaxColor`, `SyntaxKeyword`, `SyntaxHighlighter` line by line (`SyntaxLineState`) or whole text, `SyntaxToken`.
- Editing (`Quill.Code.Editing`): `CodeEditing` (Enter, empty lines, pairs and typed characters, backspace, tab and line indentation, line comments, duplication, deletion and moving of lines, Home key), `SourceScanner` / `SourceSyntax` (code, comments, strings; C# and T-SQL), `BracketMatcher`, `TextLines`, `TextSelection`, `TextEdit`, `EditResult`. Line breaks "\n" and "\r\n".
- Compilation (`Quill.Code.CSharp.Compilation`): `CompileAsync` emits the service's project (optional PDB), returns errors at editor positions and loads the assembly into a collectible context (`CSharpCompilationResult`, `CSharpCompileOptions`: assembly files, custom resolution). `CodeDiagnostic.Describe` ("Ligne x, colonne y : …"). UTF-8 sources for debug information.
- `SourceTransform` returns a `CSharpSource` (source and text position): neutralized text or wrapped in generated code; `CSharpProjectOptions.IncludeSemanticDiagnostics` and `AllowImports`.
- Removal of `AddQuillCSharp`: apps instantiate the services; `Quill.Code` no longer has any dependency.
- Raw-text contracts `ICodeCompletionProvider` (Completion) and `ICodeDiagnosticProvider` (Analysis), implemented by `ICSharpLanguageService`.
- `CSharpLanguageService(string projectName, Func<CSharpProjectOptions>?)`: service on its own project, methods on the code (`GetCompletionsAsync(code, position)`…); `CSharpProjectOptions` becomes a record with an optional name.
- `CSharpWorkspace.AddProject` only creates the project on first use (overload with deferred options); `CSharpProjectOptions.SourceTransform` and `TextReferences`; raw-text extensions of `ICSharpLanguageService` (`CSharpLanguageServiceExtensions`).
- Sources added on the fly (`CSharpProject.SetSource`, `SetSourceFileAsync`, `RemoveSource`, `ClearSources`, `Sources`, `SourcesChanged`): seen by the editor and compiled with it; their compilation errors name the file.
- `CSharpCompileOptions.Collectible` (assembly loaded for the application's whole lifetime) and `CSharpCompilationResult.Reference` (compile another project against the emitted assembly).
- Execution (`Quill.Code.CSharp.Compilation`): `CSharpCompilationResult.RunAsync` (off the calling thread, code exception rethrown as is; on cancellation, control returns immediately, `CSharpRunAbandonedException`, and `Dispose` waits for the actual end before unloading) and `RunEntryPointAsync` (exit code).
- Script runtime: `CSharpProjectOptions.IncludeScriptRuntime` generates `Log`, `LogLevel` and `Script` in the assembly, wired by reflection (`CSharpCompileOptions.Log`, `Script.CancellationToken` set by `RunAsync`): specific to each compilation, without any reference to the application. `Quill.Code.Scripting.LogLevel`, modeled on `Microsoft.Extensions.Logging`.
- `CSharpDiagnosticMapper.MapAsync`: Roslyn diagnostics computed outside Quill (emit errors) mapped back to the editor text.
